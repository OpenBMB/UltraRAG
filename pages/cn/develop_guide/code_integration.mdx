通过 `ToolCall` 调用单个已注册工具，通过 `PipelineCall` 执行完整流程。以下示例在仓库根目录运行，使用无需外部模型的 sayhello 服务器。

## ToolCall

```python
from ultrarag.api import ToolCall, initialize, shutdown

initialize(["sayhello"], server_root="servers", no_mcp=True)
try:
    result = ToolCall.sayhello.greet(name="UltraRAG")
    print(result)
finally:
    shutdown()
```

参数按关键字传入；字典使用 `**parameters` 展开。未显式传入的参数会从服务器的参数文件补齐。服务初始化状态由当前进程共享，请在重新配置服务或退出前完成正在执行的调用并释放资源。

## Async ToolCall

```python
import asyncio
from ultrarag.api import ToolCall, initialize, shutdown

async def main():
    initialize(["sayhello"], server_root="servers", no_mcp=True)
    try:
        result = await ToolCall.sayhello.greet(name="Async UltraRAG")
        print(result)
    finally:
        await shutdown()

asyncio.run(main())
```

## PipelineCall

先生成参数与服务器配置：

```bash
ultrarag build examples/experiments/sayhello.yaml --no-mcp
```

```python
from ultrarag.api import PipelineCall

result = PipelineCall(
    pipeline_file="examples/experiments/sayhello.yaml",
    parameter_file="examples/experiments/parameter/sayhello_parameter.yaml",
    no_mcp=True,
    log_level="info",
)
print(result)
```

在运行中的异步事件循环里使用 `await PipelineCall(...)`。`PipelineCall` 自行管理本次流程的执行客户端。省略 `no_mcp=True` 会使用默认 MCP 传输，需要安装 `mcp` extra；本地模式混用远程 MCP 也需要该依赖。
