---
title: "Agent 流程助手"
icon: "wand-magic-sparkles"
---

搭建器助手对兼容 OpenAI 的服务采用有次数上限的“模型 → 工具 → 结果”循环，读取实际工作区后再提出方案。其他服务保留对话模式。

## 配置并提问

使用管理员账号登录，新建或选择流程后打开助手。在设置中选择 OpenAI 或兼容的自定义服务，填写 API 基础地址（按服务要求包含 `/v1`）、模型和密钥，先测试连接。模型需要支持函数或工具调用；连接测试成功本身不能证明支持工具调用。

例如：“先检查可用的检索和生成工具，为现有集合提出一个 RAG 流程，提出前核对工具名称和输入输出映射。”嵌入地址需单独在检索器参数中配置，不能使用嵌入模型作为助手的对话模型。

## 查看工具记录

助手可以列出和检查服务器，读取已保存流程或当前草稿，读取脱敏参数及 Jinja 模板，并校验、暂存方案。真实工具结果会反馈给模型，让它修正不存在的工具或错误 YAML。展开 **工作区工具执行记录** 可查看进度和校验失败，控制台也会记录工具进度。

每次请求最多八轮模型调用，每轮最多八次工具调用，总时限三分钟。达到上限时请缩小问题范围。停止按钮取消本次模型请求并阻止后续工具分派；切换助手会话也会停止旧请求。

## 审阅、应用并测试

1. 阅读修改预览。静态校验检查 YAML 结构、已注册服务器和工具名称，以及重映射键，不会执行流程或检查外部服务是否可用。
2. 对每项方案点击 **应用** 或 **拒绝**。流程方案对应提出时选中的流程；修改 YAML 时请回到流程视图。工具循环本身不保存文件，也不执行 shell 命令。
3. YAML 修改后重新 Build，自行配置参数和凭据，再用代表性问题运行测试。核对回答、来源和控制台输出，同时使用无效配置检查报错后能否恢复。

<Warning>工作区文本和模型输出可能存在错误，请在应用前审阅路径、数据流和参数。参数工具返回内容会脱敏，也不能通过参数工具提出凭据修改。助手设置和对话历史使用浏览器本地存储，请使用可信的浏览器配置。</Warning>

循环参考 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/agent-loop/README.md) 的模型与工具结果交替模式，工具范围限定于 UltraRAG 流程搭建。
